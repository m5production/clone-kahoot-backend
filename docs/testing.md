# Тестирование

| Уровень | Где | Запуск | БД |
| --- | --- | --- | --- |
| Unit (backend) | `test/*.test.ts` — node:test через tsx, Prisma подменяется | `yarn test` | не нужна |
| Unit/component (frontend) | `*.unit.spec.ts`, `*.browser.spec.tsx` | `bun run test` | — |
| E2E (полный цикл) | `frontend/e2e` — Playwright | `bun run test:e2e` | PostgreSQL `clone_kahoot_e2e` |

## Принципы

- Интеграционные проверки — только против **PostgreSQL**, никогда SQLite.
- E2E-процесс: Playwright поднимает собранный бэкенд (`npx tsc && node dist/main.js`,
  порт 3101, `NODE_ENV=test`, `DB_*` из `E2E_DB_*` или локальный
  `postgres:postgres@localhost:5432/clone_kahoot_e2e`) и Vite :5174.
  БД сбрасывается `migrate reset` каждым запуском — не направлять на рабочую БД.
- `NODE_ENV=test` отключает in-memory rate limit (много регистраций с одного IP).
- Не запускать src через `tsx` — DI не работает без decorator metadata;
  только собранный `dist/` или `nest start`.

## Покрытие

- backend unit (10 файлов в `test/`): валидация конфигурации, scrypt-пароль,
  `auth.service`, игровой сервис — роли, один ответ на вопрос, отключения,
  изоляция комнат, завершение игры; `history.service` — запись и чтение
  истории; нормализация ответов; валидация принимаемых ответов и вариантов
  `choice`; перестановка вопросов; лимитер WS-команд.
- frontend: ~102 unit/component-теста в 25 спеках.
- e2e: ~40 тестов в 8 спеках — регистрация/вход/выход, напоминание сессии,
  CRUD квизов и вопросов (включая `choice` и мобильный конструктор), история
  и отчёт игры, мобильный экран ведущего, полный live-цикл (ведущий + 2
  игрока), вторая игра без перезагрузки, завершение при уходе ведущего, отказ
  во входе в незапущенную игру.

Не покрыто: откат транзакции replace-ответов (реализован `$transaction`),
истечение TTL сессии, конкурентные запуски одной игры (только unit).
